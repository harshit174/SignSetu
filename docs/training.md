# Training from scratch

The trained models ship in `models/`, so you only need this page to retrain or to rebuild the metrics, figures and demo GIF.

Developed on **Fedora Linux 44** (AMD Ryzen 7, 14 GB RAM, NVIDIA RTX 5050 Laptop GPU, PostgreSQL 18.6). The app itself also runs on macOS; Windows has not been tested.

## Prerequisites

- Python **3.11**, Git, PostgreSQL **16+** (the notebook needs it; the app does not)
- An NVIDIA GPU is recommended (about 25 min here); inference runs on CPU
- About 3 GB of disk for the dataset (2.2 GB) and caches

## 1. Environment

```bash
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements-train.txt
python -m ipykernel install --user --name signsetu --display-name "Python 3.11 (SignSetu)"
```

`requirements-train.txt` pulls PyTorch from the CUDA 12.8 index (required for RTX 50-series GPUs; older GPUs can use any CUDA build). Some pins are deliberate and commented in the file, for example `numpy 1.26` because MediaPipe 0.10.21 needs NumPy < 2.

## 2. PostgreSQL

Install the server and create a role that can log in over TCP with a password. Fedora example:

```bash
sudo dnf install postgresql-server postgresql
sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql
sudo -u postgres psql -c "CREATE ROLE signsetu LOGIN CREATEDB PASSWORD 'choose-a-password';"
```

`pg_hba.conf` must accept password (`scram-sha-256`) logins for `127.0.0.1` and `::1`. Fedora defaults to `ident`; Debian/Ubuntu and the Windows installer already use passwords. The notebook creates the database and tables itself.

## 3. Configuration and dataset

```bash
cp .env.example .env      # then edit PGPASSWORD and DATASET_ROOT
```

Download the files of Zenodo record [23004815](https://zenodo.org/records/23004815) (`dataset_consolidated.h5`, `dataset_consolidated.h5.sha256`, `manifest_consolidated.csv`, `quality_flags.csv`) into one folder and point `DATASET_ROOT` at it.

## 4. Run the notebook

Open **`SignSetu.ipynb`**, choose the kernel *Python 3.11 (SignSetu)* and **Run All**. With no manual edits it will:

environment check → bootstrap PostgreSQL → verify and load the dataset → split → train the baseline and the Transformer → evaluate → export ONNX → draw figures and the demo GIF → update the README metrics block → write the Streamlit app → start it at http://localhost:8501.

Re-running skips finished work (feature cache, config-hash-matched checkpoints).

| Flag (config cell) | Default | Effect |
|---|---|---|
| `SMOKE_TEST` (env `SIGNSETU_SMOKE=1`) | off | 10 classes, 3 epochs; outputs go to `models/smoke/`, `reports/smoke/`, `assets/figures_smoke/` |
| `FORCE_RELOAD` | `False` | re-read the HDF5 file instead of `data/base_f16.npy` |
| `FORCE_RETRAIN` | `False` | retrain even if a matching checkpoint exists |
| `SEED` | `42` | seeds Python, NumPy and PyTorch |
| `LAUNCH_APP` (env `SIGNSETU_NO_LAUNCH=1` turns it off) | on | start Streamlit at the end |
| `APP_PORT` | `8501` | first port tried (falls back to 8502–8510) |
| `STOP_APP` | `False` | set `True` and run only the last cell to stop the app |

First full run is about 24 minutes (BiGRU 8 min, Transformer 16 min on the GPU); a cached re-run takes about 30 seconds.

## Editing the app

`app.py`, `isl_core.py`, `isl_lang.py` and `.streamlit/config.toml` are **generated by the notebook**. Edit them directly while iterating, then fold the change back into the notebook:

```bash
python tools/sync_notebook.py          # write the edited files into SignSetu.ipynb
python tools/sync_notebook.py --check  # CI runs this: fails if the notebook and files differ
```

`assets/theme.css` and `assets/speech.js` are plain files that `app.py` loads at start-up; edit them in place.
